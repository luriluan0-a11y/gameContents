Auto-Implemented Property

클래스의 데이터를 외부로부터 안전하게 보호하면서도 읽기를 허용하는 C#의 캡슐화 패턴입니다.

public  string  Title  {  get;  private set;  }
01 — Anatomy
코드 구조 해부

한 줄짜리 코드지만 각 키워드가 서로 다른 역할을 합니다.

public접근 제한자   string타입   Title이름  {  get읽기 ;  private내부전용   set쓰기 ; }

02 — Comparison
필드 vs 프로퍼티

단순 필드와 비교했을 때 프로퍼티가 왜 더 안전한지 확인합니다.

✗  필드 (Field) — 위험
class Book
{
    // 외부에서 직접 수정 가능!
    public string Title;
}

var b = new Book();
b.Title = "C# 입문";  // ← 아무나 변경 가능
b.Title = "";        // ← 빈 값도 가능
b.Title = null;     // ← null도 가능
✓  프로퍼티 — 안전
class Book
{
    // 외부: 읽기만 / 내부: 읽고 쓰기
    public string Title
        { get; private set; }
}

var b = new Book();
b.Title = "C# 입문";
// ↑ 컴파일 오류! 외부에서 set 불가
03 — Example
실제 동작 예시

클래스 내부에서는 자유롭게 수정하고, 외부에서는 읽기만 허용하는 패턴입니다.

Book.cs C# 
class Book
{
    public string Title  { get; private set; }
    public string Author { get; private set; }
    public int    Pages  { get; private set; }

    // 생성자: 클래스 내부 → set 가능 ✓
    public Book(string title, string author, int pages)
    {
        Title  = title;
        Author = author;
        Pages  = pages;
    }

    // 메서드: 클래스 내부 → set 가능 ✓
    public void UpdateTitle(string newTitle)
    {
        Title = newTitle;   // ✓ 내부에서는 수정 가능
    }
}

// ── 외부에서 사용 ──
var book = new Book("C# 입문", "홍길동", 320);

Console.WriteLine(book.Title);    // ✓ "C# 입문" — get 가능
Console.WriteLine(book.Author);   // ✓ "홍길동"  — get 가능

book.Title = "다른 제목";          // ✗ 컴파일 오류! private set
book.UpdateTitle("개정판");      // ✓ 메서드를 통해서만 변경 가능
✓ 핵심 규칙 private set이 붙으면 클래스 내부(생성자·메서드)에서는 값을 자유롭게 변경할 수 있지만, 클래스 외부에서는 읽기(get)만 가능합니다.
04 — Access Control
접근 권한 정리

위치(내부/외부)에 따라 읽기·쓰기 가능 여부가 달라집니다.

위치 읽기 (get) 쓰기 (set) 비고
클래스 내부 (생성자, 메서드) ✓ 가능 ✓ 가능 private set이므로 내부는 자유롭게
클래스 외부 (다른 클래스, Main) ✓ 가능 ✗ 불가 컴파일 오류 발생
상속받은 자식 클래스 ✓ 가능 ✗ 불가 private은 자식도 접근 불가
💡 protected set vs private set 자식 클래스에서도 수정이 필요하다면 private set 대신 protected set을 사용하면 됩니다. 자식 클래스는 허용되지만 외부는 여전히 차단됩니다.
05 — Variants
다양한 프로퍼티 패턴

상황에 따라 선택할 수 있는 프로퍼티 변형들입니다.

읽기 전용 (C# 6.0+)
public string Title { get; }
생성자에서만 초기화 가능. 이후 완전히 변경 불가. 불변 객체에 적합.
init 접근자 (C# 9.0+)
public string Title { get; init; }
객체 초기화 시에만 값 설정 가능. 이후 변경 불가. record 타입에서 자주 사용.
완전 공개
public string Title { get; set; }
누구나 읽고 쓸 수 있음. DTO나 단순 데이터 모델에 사용.
완전 차단
public string Title { get; private set; }
외부는 읽기만, 내부에서만 수정. 가장 일반적인 캡슐화 패턴.

한 줄 요약

  • 프로퍼티는 클래스 데이터를 안전하게 노출하는 C#의 핵심 기능입니다.
  • private set은 "밖에서는 읽기만, 안에서는 읽고 쓰기 모두 가능"을 의미합니다.
  • 외부에서 obj.Title = "값"을 시도하면 컴파일 오류가 발생합니다.
  • 이것이 바로 객체지향의 캡슐화(Encapsulation) 원칙입니다.
