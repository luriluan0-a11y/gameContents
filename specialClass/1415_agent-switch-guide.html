Agent와 사랑에 빠지지 않기

언제든 갈아탈 수 있는 환승연애를 위한 가이드

AI 에이전트는 몇 달마다 새로 나오고, 어제의 최고가 오늘은 평범해집니다. 한 도구에 내 일과 기억을 다 맡겨 두면 갈아타기 어렵습니다. 오늘은 내 지식은 내 폴더에 두고, 에이전트는 그때그때 가장 좋은 것을 골라 쓰는 법을 익힙니다.

기억은 내 파일에, 일은 그때의 에이전트에게.
그래야 언제든 환승할 수 있습니다.
① 나의 두뇌를 컴퓨터에 옮기기 ② 어떤 Agent를 쓸까 ③ 내 업무의 불편한 점 찾기 ④ grill-me로 기획서 쓰기 ⑤ 사례

00왜 "환승연애"인가

한 에이전트에만 정을 주면 생기는 일

✕ 사랑에 빠진 상태

  • 업무 맥락이 한 서비스의 대화 기록 안에만 있다
  • 새 에이전트로 옮기면 처음부터 다시 설명해야 한다
  • 요금이 오르거나 서비스가 바뀌어도 떠나기 어렵다

○ 언제든 환승 가능한 상태

  • 업무 맥락이 내 폴더의 마크다운 파일에 있다
  • 어떤 에이전트든 그 폴더를 열면 바로 이어서 일한다
  • 더 좋은 도구가 나오면 부담 없이 갈아탄다

01나의 두뇌를 컴퓨터에 옮기기

에이전트가 읽을 수 있게, 내 자료를 정해진 자리에 둔다

PARA — 자료를 네 칸으로 나눈다

PProjects끝이 있는 일. 마감과 목표가 있다
AAreas끝없이 책임지는 영역. 건강, 재정, 맡은 업무
RResources나중에 쓸지 모르는 관심 주제·참고 자료
AArchive위 셋에서 끝났거나 쉬는 것

Johnny.Decimal — 칸마다 번호를 붙인다

폴더 이름 앞에 번호를 붙여 순서와 자리를 고정합니다. 번호만 말해도 사람과 AI가 같은 폴더를 찾습니다.

# 예시 (PARA + 번호) 000_inbox/ ← 아직 자리를 못 정한 것, 일단 여기 100_working/ ← Projects · Areas 101_매일할일/ 102_고객사_제안/ 300_collected/ ← Resources: 모은 자료 400_archive/ ← 끝난 일
PARA 원문 (Forte Labs) → Johnny.Decimal 공식 사이트 →

실습 ① 다운로드 폴더 정리하기

  • 다운로드 폴더나 카카오톡 받은 파일 폴더를 열어 봅니다.
  • 개인정보가 들어 있다면 그 폴더는 쓰지 말고, 개인정보가 없는 다른 폴더로 실습합니다.
  • 파일 목록을 에이전트에게 보여 주고, PARA + 번호 구조로 나눌 안을 받아 봅니다.

소크라테스 문답법 — AI가 묻고, 내가 답한다

정리 기준은 AI가 정하는 게 아니라 내가 정합니다. AI에게 답을 달라고 하지 말고 질문을 하게 하면, 내 머릿속 분류 기준이 말로 나옵니다.

너는 소크라테스처럼 질문하는 정리 코치야. 답이나 정리안을 먼저 주지 말고, 한 번에 질문 하나씩만 해 줘. 목표: 내 [다운로드 폴더]를 PARA(Projects·Areas·Resources·Archive)와 번호 붙인 폴더 구조로 정리하는 것. 1. 내가 지금 진행 중인 일, 계속 책임지는 영역, 모아 두는 자료가 무엇인지 차례로 물어봐. 2. 내 답이 모호하면 꼬리 질문으로 구체화해 줘. 3. 질문이 충분히 쌓이면 그때 폴더 구조(번호 포함) 초안을 제안하고, 내가 고칠 점을 물어봐.

02어떤 Agent를 쓰십니까?

오늘은 셋 중 무엇을 써도 됩니다. 같은 폴더를 열면 같은 일을 할 수 있어야 합니다.

Claude
Anthropic · Claude Code

긴 문서 정리·글쓰기·코드 작업. 폴더의 규칙 문서를 읽고 따른다.

Codex
OpenAI

코드 작성·수정에 강한 코딩 에이전트. ChatGPT 계정으로 쓴다.

Gemini
Google

Google 계정·Workspace와 잘 어울린다. 무료로 시작하기 쉽다.

도구는 VS Code 하나로

  • 편집기(IDE)는 VS Code를 씁니다.
  • 각 에이전트는 VS Code의 확장(Extension)으로 설치합니다. 확장 탭(Ctrl+Shift+X)에서 이름으로 검색합니다.
  • 에이전트를 바꿔도 열어 둔 폴더와 파일은 그대로입니다. 이것이 환승의 핵심입니다.
💡

규칙 문서 한 장을 폴더에 둡니다. 폴더 맨 위에 "이 폴더는 무엇이고, 파일은 어디에 두고, 무엇은 건드리지 마라"를 적은 마크다운(예: AGENTS.md)을 두면, 어떤 에이전트로 갈아타도 같은 규칙으로 일합니다.

03나의 업무에서 불편한 점 찾기

반복적이고 덜 중요한 일은 AI에게, 중요한 일은 나에게

⚠️

개인정보부터 지킵니다. 이름·학번·연락처처럼 사람을 알아볼 수 있는 정보가 AI에 들어가지 않게 합니다. 에이전트는 암호를 건 zip 파일도 풀 수 있습니다. 종이에 쓴 것 말고는 컴퓨터에 있는 모든 것이 노출될 수 있다고 생각하세요.

개인정보 폴더는 아예 못 읽게 설정한다

"읽지 마"라고 부탁하는 것으로는 부족합니다. 에이전트 설정에서 접근 자체를 막아 둡니다. Claude Code라면 프로젝트의 .claude/settings.json에 이렇게 적습니다.

{ "permissions": { "deny": [ "Read(./개인서류/**)", "Edit(./개인서류/**)" ] } }

다른 에이전트도 각자의 설정으로 막아야 합니다. 설정은 에이전트마다 따로입니다.

자동화 사례

뉴스레터 만들어 배포하기

내용 정리(마크다운)→AI 검토→웹용·메일용 HTML→GitHub 게시·텔레그램으로 링크→배포 요청

블로그 글쓰기

글감 정리(마크다운)→검토→이미지 생성→HTML로 만들기→복사해 직접 발행

네이버 블로그 자동 발행은 차단 사유가 될 수 있어 마지막은 사람이 한다(반자동).

채용 정보 전달하기

채용 사이트에서 정보 추출→HTML 제작→GitHub 게시→커뮤니티에 공유

서류 피드백 해 주기

개인정보 뺀 서류 받기→내 피드백 기준(마크다운)으로 검토→고칠 수 있는 피드백 파일 전달

평가 시스템 만들기

시험지·답안 규칙 정리→채점 시스템 개발→파일 올리면 세부 평가서

성적 처리를 AI에 그냥 맡기면 이름·학번이 노출된다. 그래서 AI에게는 "채점 규칙을 가진 시스템"을 만들게 하고, 실제 채점은 그 시스템이 내 컴퓨터에서 한다.

홈페이지 카드뉴스 만들기

이달 소식 정리→썸네일·카드뉴스 제작→홈페이지 업데이트

남색 단계는 AI가 하고, 흰색 단계는 사람이 합니다.

AI에게는 반복적이고 덜 중요한 일을,
나는 중요한 일을 합니다.

04grill-me로 "나에게 필요한 시스템" 기획서 쓰기

AI가 나를 끝까지 캐물어, 무엇을 만들지 분명해질 때까지

스킬(Skill)이란?

에이전트에게 특정 일을 하는 방법을 적어 준 설명서 폴더입니다. 남이 잘 만든 스킬을 설치하면 내 에이전트가 그 방식대로 일합니다. skills.sh는 이런 스킬을 찾고 설치 수 순위를 볼 수 있는 공개 목록입니다.

skills.sh 둘러보기 →

grill-me 스킬

  • 보통은 내가 AI에게 묻지만, grill-me는 반대로 AI가 나에게 질문을 퍼붓습니다.
  • 결정할 것을 나뭇가지처럼 펼쳐 놓고, 정해지지 않은 가지가 남지 않을 때까지 묻습니다.
  • 내가 동의하기 전에는 아무것도 만들지 않습니다. 기획서를 쓰기 전 단계에 딱 맞습니다.
  • Matt Pocock의 스킬 모음(mattpocock/skills)에 들어 있습니다.

Claude Code에 설치하는 명령(터미널에서 실행):

npx -y skills add mattpocock/skills --skill grill-me --agent claude-code

설치 방법은 바뀔 수 있으니 실행 전에 skills.sh의 grill-me 페이지에서 최신 명령을 확인하세요. 다른 에이전트는 --agent 뒤의 이름을 바꿉니다.

실습 ② 기획서 쓰기

  1. 03에서 찾은 내 업무의 불편한 점 하나를 고릅니다.
  2. 에이전트에게 grill-me로 시작하자고 말하고, 아래 요청문을 붙여 넣습니다.
  3. 질문에 하나씩 답합니다. 모르면 "모르겠다, 선택지를 줘"라고 해도 됩니다.
  4. 질문이 끝나면 기획서를 마크다운 파일로 저장합니다. 이 파일이 다음 에이전트에게도 그대로 넘겨줄 내 자산입니다.
grill-me로 진행해 줘. 내 업무에서 불편한 점: [예: 매주 같은 형식의 보고서를 손으로 다시 만든다] "나에게 필요한 시스템" 기획서를 쓰려고 해. 한 번에 질문 하나씩, 결정할 것이 남지 않을 때까지 물어봐. 끝나면 아래 형식으로 마크다운 기획서를 만들어 줘. - 한 줄 소개 - 누가, 언제 쓰나 - 지금 방식과 불편한 점 - 시스템이 하는 일 (입력 → 처리 → 출력) - 개인정보·보안 주의점 - 첫 버전에 넣을 것 / 나중에 넣을 것
