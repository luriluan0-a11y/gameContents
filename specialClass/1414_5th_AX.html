개념 1

왜 개인 위키는 실패할까

지식이 부족해서가 아니라, 유지 관리 비용이 가치보다 빨리 커지기 때문입니다.

🔗새 노트마다 링크 달기
📋목록·목차 고치기
🧩페이지끼리 내용 맞추기

이런 행정 일을 북키핑이라고 합니다. LLM 위키는 북키핑을 AI에게 넘깁니다. 안드레 카파시(OpenAI 창립 멤버)가 자신의 실험을 공개하며 알려졌습니다. 그의 비유는 "옵시디언은 작업대, LLM은 프로그래머, 위키는 코드"입니다.

핵심
쿼리 답을 다시 위키에 저장하는 것이 RAG와 다른 점입니다. 묻는 일 자체가 쌓입니다. 규칙이 부실하면 위키가 커지는 순간 AI도 관리하지 못하니 좁은 주제 하나로 시작합니다.

안전 규칙

1

위키 폴더 하나만 연다

내 문서 전체나 바탕화면을 AI에게 열지 않습니다.

2

민감한 파일은 넣지 않는다

주민번호·계좌·비밀번호가 든 파일은 위키 폴더 밖에.

3

지우기 전에 멈춘다

AI가 파일을 지우거나 덮어쓰려 하면 멈추고 확인합니다.

실습 순서

폴더 만들기 → 인제스트 → 확인 → 쿼리 · 린트

실습 0 · 폴더 만들기 (17:25~)

내취업위키/ ├── AGENTS.md ← 규칙 (아래 "규칙 파일"을 붙여 넣기) ├── 00_인덱스.md ← 빈 파일로 시작 ├── 00_로그.md ← 빈 파일로 시작 ├── 원문/ ← 공고, 회사 조사, 공부 메모 └── 위키/ ├── 소스/ ├── 개념/ └── 종합/
  1. 옵시디언에서 새 보관소(볼트) 만들기 → 이름 내취업위키
  2. 위 폴더와 파일을 만들고, AGENTS.md에 규칙을 붙여 넣은 뒤 [주제]를 바꿉니다.
  3. 원문/에 자료 2~3개를 새 노트로 붙여 넣습니다. 예) 공고_A사_QA.md, 공부메모_테스트케이스.md

주제는 취업 준비가 아니어도 됩니다. 자격증 공부, 관심 업계 소식처럼 자료가 계속 들어오는 좁은 주제 하나면 됩니다.

실습 1 · 인제스트 (17:50~)

  1. ChatGPT 데스크톱 앱에서 Codex를 열고 작업 폴더로 내취업위키를 고릅니다.
  2. 인제스트 프롬프트를 보냅니다. 원문은 하나씩 넣습니다.
  3. 옵시디언에서 새 페이지, [[ ]] 링크, 인덱스, 로그를 보고 그래프 뷰를 엽니다.

실습 2 · 확인과 내 생각 (18:40~)

  1. AI가 만든 소스 페이지를 원문과 나란히 엽니다.
  2. 원문에 없는 말, 다른 숫자·날짜·회사 이름을 찾습니다. 있으면 "근거가 없으면 지워 줘".
  3. 확인한 페이지 속성에 checked: 2026-11-06을 적습니다 (4차시).
  4. 개념 페이지 하나에 > 내 생각: 한두 줄을 직접 씁니다.

실습 3 · 쿼리와 린트 (19:05~)

  1. 쿼리 프롬프트로 묻고, 답이 좋으면 종합 페이지로 저장하게 합니다.
  2. 린트 프롬프트로 점검하고 보고를 읽습니다. 고칠지는 내가 정합니다.
규칙 파일 · 학생 배포용

AGENTS.md — 복사해서 [주제]만 바꾸기

위키를 시작할 때 가장 먼저 씁니다. 쓰면서 고쳐도 됩니다.

# 내 위키 규칙 이 폴더는 [주제] 위키다. AI는 작업 전에 이 파일과 00_인덱스.md를 먼저 읽는다. ## 폴더 - 원문/ : 내가 넣은 자료. 읽기만 하고 절대 고치거나 지우지 않는다. - 위키/소스/ : 원문 1개당 요약 페이지 1개. 파일 이름: 소스_짧은제목.md - 위키/개념/ : 개념·회사·직무 1개당 페이지 1개. 파일 이름: 이름 그대로 (예: 테스트케이스.md, A사.md) - 위키/종합/ : 여러 페이지를 비교·연결한 글, 좋은 질문의 답 - 00_인덱스.md : 모든 위키 페이지 목록과 한 줄 설명 - 00_로그.md : 작업 기록. 맨 아래에 "- 날짜 [작업] 내용" 한 줄씩 ## 페이지 규칙 - 첫 줄에 한두 문장 요약을 쓴다. - 모든 내용 뒤에 근거 소스 페이지를 [[소스_...]]로 링크한다. 원문에 없는 내용은 쓰지 않는다. - 관련 페이지는 본문에서 [[ ]]로 잇고, 끝에 "## 관련" 목록을 둔다. - AI의 해석은 "> 해석:"으로 시작해 구분한다. - "> 내 생각:" 블록은 내가 쓴다. AI는 만들지도, 고치지도, 지우지도 않는다. - 같은 개념을 다른 이름으로 또 만들지 않는다. 먼저 00_인덱스.md에서 찾는다. - 자료끼리 내용이 다르면 지우지 말고 "## 다른 내용" 칸에 둘 다 적는다. ## 작업 - 인제스트: 원문 하나를 끝까지 읽는다 → 소스 페이지를 만든다 → 관련 개념 페이지를 고치거나 새로 만든다 → 00_인덱스.md에 등록 → 00_로그.md에 한 줄. - 쿼리: 00_인덱스.md에서 관련 페이지를 찾아 읽고 답한다. 위키에 없으면 없다고 말한다. 내가 저장하라고 하면 위키/종합/에 저장하고 인덱스·로그에 남긴다. - 린트: 인덱스에 없는 페이지, 아무 데서도 링크되지 않은 페이지, 깨진 링크, 근거 소스가 없는 내용, 페이지끼리 다른 내용을 찾아 보고만 한다. 고치는 것은 내가 정한다. ## 하지 말 것 - 원문/ 폴더의 파일을 고치거나 지우기 - 내가 넣지 않은 자료를 인터넷에서 찾아 넣기 - 이 폴더 밖의 파일 건드리기 - 파일 지우기 (필요하면 나에게 먼저 묻는다)
프롬프트 · 학생 배포용

인제스트 · 쿼리 · 린트 프롬프트

모든 프롬프트는 "AGENTS.md를 먼저 읽어 줘"로 시작합니다. [ ] 안을 바꿔 쓰세요.

인제스트 (넣기)

먼저 AGENTS.md와 00_인덱스.md를 읽어 줘. 그다음 원문/[파일 이름]을 AGENTS.md의 "인제스트" 순서대로 처리해 줘. 원문에 없는 내용은 쓰지 마. 끝나면 새로 만들거나 고친 파일 목록과, 각 파일에서 무엇을 바꿨는지 한 줄씩 알려 줘.

쿼리 (묻기)

먼저 AGENTS.md와 00_인덱스.md를 읽어 줘. 그다음 위키만 근거로 이 질문에 답해 줘: [질문]. 답의 문장마다 근거 페이지를 [[ ]]로 달아 줘. 위키에 없는 내용이면 "위키에 없음"이라고 말해 줘. 아직 저장하지는 마.
이 답을 위키/종합/[제목].md로 저장하고 인덱스와 로그에 남겨 줘.

린트 (점검)

먼저 AGENTS.md를 읽어 줘. 그다음 위키 전체를 AGENTS.md의 "린트" 기준으로 점검해서 표로 보고해 줘. 파일은 고치지 마.

AI가 규칙을 어길 때

"원문 폴더는 고치지 마. 방금 바꾼 것을 되돌려 줘."
"그 내용의 근거 원문이 어디야? 없으면 지워 줘."
"> 내 생각: 블록은 내가 쓰는 거야. 원래대로 돌려놔 줘."
