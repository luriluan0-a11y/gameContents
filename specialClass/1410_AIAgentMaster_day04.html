03

로컬 모델 사용

  • 어차피 계속 바뀌는 AI 세상에서, 조금 멍청하지만 로컬 모델을 사용해서 구동하면 비용은 절감됨
  • "에이전트를 로컬 모델로 쓴다"는 건, Hermes 같은 에이전트가 답변을 생성할 때 OpenAI·Anthropic·Google 같은 회사의 서버(클라우드 API)에 요청을 보내는 대신, 내 컴퓨터(또는 내가 관리하는 서버) 안에서 직접 돌아가는 LLM을 사용한다는 뜻임

클라우드 모델 vs 로컬 모델

Cloud

클라우드 모델 (GPT, Claude, Gemini)

  • 내 요청이 인터넷을 통해 회사 서버로 전송됨
  • 서버에서 계산 → 결과를 다시 받음
  • 인터넷 연결 필수, 사용량만큼 API 비용 발생
Local

로컬 모델

  • 모델 파일(가중치)을 내 컴퓨터에 다운로드해서 저장
  • 계산(추론)도 내 컴퓨터의 GPU/CPU가 직접 수행
  • 인터넷 연결 없이도 동작 가능, API 비용 없음 (전기세는 나가지만)
04

실제로 어떻게 쓰나?

  • 보통 Ollama나 LM Studio 같은 도구로 로컬 모델을 서버처럼 띄워두고, Hermes 같은 에이전트가 그 로컬 서버에 "OpenAI 호환 API" 형식으로 요청을 보내는 방식이 일반적임
  • Hermes는 OpenAI, OpenRouter, Nous Portal뿐 아니라 자체 OpenAI 호환 엔드포인트도 지정 가능 — 로컬에서 돌아가는 모델도 이 방식으로 연결 가능하다는 것임

왜 쓸까?

장점단점
API 비용 없음 (한 번 다운로드하면 무료)성능이 GPT-5, Claude Sonnet 5 급 최상위 모델보다 대체로 떨어짐
데이터가 외부로 안 나감 (프라이버시)좋은 GPU 없으면 느리거나 아예 못 돌림 (VRAM 많이 필요)
인터넷 없어도 동작모델 관리·업데이트를 직접 해야 함
무제한 요청 (rate limit 없음)설정이 클라우드 API 대비 번거로움

구글 이메일 설정하기

  • hermes에 요청하기
예시 프롬프트 
https://github.com/pimalaya/himalaya/releases himalaya 설치 좀 해줘
  • hermes가 himalaya가 설치되어 있지 않다고 해서 설치를 요청함
  • 요청했더니 앱 비밀번호가 필요하다고 해서 어떻게 하냐고 물어보니 아래처럼 알려줌

앱 비밀번호 만드는 법 (5분)

  1. myaccount.google.com/apppasswords에서 이메일에 로그인
  2. 2단계 인증이 꺼져 있으면 먼저 켜기 (설정 → 보안)
  3. "앱 이름"에 himalaya 입력 → [만들기]
  4. 16자리 코드(예: abcd efgh ijkl mnop)가 화면에 뜸 → 그걸 복사
Hermes 응답 (한계 고지)

좋아, 할 일 바뀐 건 확인했어. 근데 이건 내가 "구글 계정에 들어가서" 직접 할 수 있는 건 아니야. 솔직하게 한계부터 짚어줄게 — 진짜 강자는 모르는 척 안 하거든.

내가 뭘 할 수 있고 없는지, 방금 직접 확인해 봤어.

확인한 것
- 파이썬 3.11은 있음. (uv는 권한 문제로 안 돌아가긴 하는데, 파이썬 자체는 됨)
- 네 컴퓨터 안에 구글 계정 접근 권한 파일(토큰, 크레덴셜, oauth 파일)은 아무것도 없음. 검색해도 0건.
- 즉, 지금 이 환경에서 네 구글 이메일에 직접 로그인해서 필터를 거는 건 불가능해. 네 계정 비밀번호나 oauth 승인 없이는 당연히 못 들어가지.

  • 텔레그램 봇은 못한다고 했지만, Hermes는 "이제 백그라운드로 실행해서 668개 메일을 배치 이동시키겠습니다 (시간이 걸릴 수 있어 백그라운드)"라고 답함
  • 정기로 진행해달라고 한 적은 없는데 매일 혹은 정기적으로 진행한다고 해서 내가 요청할 때만 진행하라고 했음, 끝내 오전 7시에 해준다고 해서... 하... LLM의 성능 문제가 아닐까 함
  • 다양한 일상의 반복을 AI에게 도움을 요청해봄
