01

에이전트 vs AI 에이전트

"에이전트"와 "AI 에이전트"는 자주 헷갈리는 개념인데, 핵심 차이는 "판단을 누가 내리냐"예요.

Rule-based

에이전트 (Agent)

  • 원래 컴퓨터 과학에서 "에이전트"는 환경을 인식하고, 정해진 규칙에 따라 행동하는 프로그램/시스템 전체를 가리키는 넓은 개념
  • AI가 없어도 성립함 — 예: 온도 감지하면 자동으로 히터 켜는 온도조절기, if-else 규칙으로 움직이는 게임 NPC, 정해진 스케줄대로 파일 백업하는 크론 작업
  • 핵심: 미리 정해진 규칙(rule-based)을 따름 → 판단력이 없음, 정해진 조건만 확인
Model-driven

AI 에이전트 (AI Agent)

  • LLM(거대 언어모델) 같은 AI가 "두뇌" 역할을 해서, 상황을 이해하고 스스로 계획을 세워 행동하는 에이전트
  • 정해진 규칙이 아니라 자연어로 된 목표를 주면, AI가 알아서 단계를 쪼개고, 도구를 선택하고, 실행 결과 보고 다음 행동을 결정함
  • 예: Hermes나 OpenClaw처럼 "로그 분석해서 요약해줘"라고 하면, AI가 스스로 "어떤 파일을 볼지 → 어떻게 파싱할지 → 어떤 형식으로 정리할지" 판단해서 실행
구분에이전트 (일반)AI 에이전트
판단 방식미리 정해진 규칙AI가 상황 보고 스스로 판단
유연성낮음 (정해진 조건만)높음 (예상 못한 상황도 대응)
예시온도조절기, 크론 작업, 게임 NPCHermes, OpenClaw, Claude Code
핵심 기술if-else, 스케줄러LLM + 도구 사용(tool use)
한 문장 요약

모든 AI 에이전트는 에이전트지만, 모든 에이전트가 AI 에이전트는 아니다 — "규칙을 따르나(에이전트)" vs "AI가 스스로 생각해서 판단하나(AI 에이전트)"의 차이

AI 에이전트가 실제로 많이 쓰이는 영역

01

코딩 / 개발

  • 가장 널리 쓰이는 영역. Claude Code, Cursor, GitHub Copilot Agent 등
  • 코드 작성, 버그 수정, PR 생성, 테스트 실행까지 자동화
02

개인 비서 / 메신저 자동화

  • Luke님이 쓰시는 Hermes, OpenClaw처럼 텔레그램/디스코드/슬랙에서 대화하며 일정 관리, 리마인더, 정보 조회
  • 이메일 정리, 회의 요약
03

고객 서비스 / 상담

  • 챗봇 넘어서 실제로 티켓 처리, 환불 처리, 계정 조회 같은 액션까지 실행
  • 회사 CS팀 1차 응대 자동화
04

리서치 / 데이터 분석

  • 여러 사이트 돌아다니며 정보 수집 → 정리 → 보고서 작성
  • 경쟁사 분석, 시장 조사, 논문 요약
05

업무 자동화 (RPA + AI)

  • 스프레드시트 정리, 반복 문서 작업, 데이터 입력
  • 기존 RPA(단순 규칙 기반)에 판단력이 추가된 버전
06

콘텐츠 제작

  • 블로그 글, SNS 포스팅 초안 작성 → 검토 → 발행까지 파이프라인화
  • Luke님 블로그 워크플로우처럼, 스킬로 정형화해서 반복 생산
07

개인 비서형 (일정/이메일/여행 예약)

  • 캘린더 확인 → 회의 잡기, 항공권/호텔 비교 예약
08

교육 / 튜터링

  • 학생 수준에 맞춰 문제 생성, 첨삭, 개인화된 학습 경로 제시
  • Luke님 vibe coding 수업처럼, 학생별 진도 관리
09

시스템 관리 / 운영(DevOps)

  • 서버 모니터링, 장애 감지하면 자동으로 진단·복구 (아까 보신 Hermes가 OpenClaw 크래시 자동 복구한 사례처럼)
핵심 포인트

가장 활발한 3곳 꼽으면 코딩 자동화 > 개인 비서(메신저 기반) > 업무 자동화예요. 수업에서 다루실 거면 학생들이 직접 체감할 수 있는 예시(챗봇, 숙제 도우미, 게임 NPC 등) 위주로 좁혀서 설명하는 게 이해에 더 좋을 수 있어요.
