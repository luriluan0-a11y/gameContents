02

AI 에이전트 기능 차이

  • 철학 자체가 다르기 때문에 성장시켜보고 마음에 드는 것을 선택하거나 더 많이 사용하면 됨
구분OpenClawHermes
만든 곳 오픈소스 커뮤니티 기반 개인 비서 프레임워크 AI 모델(Hermes, Nomos, Psyche)도 만드는 Nous Research가 개발
철학 "잘 세팅된 비서" — 사람이 정체성·규칙 파일을 써주고, 정해진 스킬을 필요할 때 꺼내 씀 "스스로 성장하는 직원" — 일하면서 자기 노하우(스킬)를 알아서 만들고 다듬음
봇 끼리 대화 봇 끼리 대화하는 기능 제공 기능 없음
토큰 소모 매 에이전트 실행마다 자체적으로 시스템 프롬프트를 구성하는데, 별도의 런타임 기본 프롬프트는 없고 기본 지침·스킬 목록·워크스페이스 파일 등 여러 레이어를 조합해서 만듦. 설치된 스킬 전체를 시스템 프롬프트에 다 집어넣지 않고, 스킬의 이름·설명·경로만 담은 압축된 목록만 넣어두었다가 모델이 필요하다고 판단하면 그때 SKILL.md를 읽어오는 방식이라, 토큰을 아끼는 구조임 구조상 비슷하게, SKILL.md 기반 워크플로우나 설정이 에이전트의 "행동 규칙"을 정의하는 시스템 프롬프트 성격이고, 텔레그램/디스코드로 들어오는 실제 대화가 사용자 입력임. 헤르메스는 엄청 길고 무거워 토큰 사용량이 큰 편임. 이미 수백 개의 스킬이 설치되어 있어서 그 스킬을 로딩하는 것도 포함되어 더욱 무겁다고 알려져 있음
스킬 획득 방식 스킬을 통째로 미리 다 읽지 않고 이름·설명·경로만 목록으로 갖고 있다가 필요할 때 해당 SKILL.md를 골라 읽는 방식. 대부분 사람이 미리 작성해둔 스킬 경험에서 새 스킬을 스스로 생성하고, 실행하면서 다듬는 방식 — skill_manage 툴로 학습하며 스킬을 만들고 고침
03

반복 작업이 뭐가 있는지 물어보기

예시 프롬프트 
지금까지 저랑 작업하면서, 자주 반복한 작업이 뭐가 있었나요? 그중에 자동화하면 편해질 만한 걸 몇 개 추천해주세요. 왜 그게 반복인지, 자동화하면 뭐가 좋아지는지도 같이 알려주시면 좋겠습니다.
Hermes 응답

MEMORY.md, memory/, 등록된 알림 작업을 직접 봤습니다.

자주 반복된 작업은 꽤 분명합니다.

1. 일정 기록과 알림 설정
왜 반복인가: 기억 파일에서 일정/알림/예약/회의/면담 계열 기록이 압도적으로 많습니다. 특강, 병원, 면담, 회의, 가족 일정, 노조 일정이 계속 들어오고, 알림 시간도 "1시간 전", "전날 저녁", "당일 아침"으로 반복됩니다.
자동화하면 좋은 점: 루리가 "OOO 면담 7/28 13시"처럼 짧게 보내면 날짜·요일 확인, 충돌 체크, cron 알림, 메모 기록까지 한 번에 처리할 수 있습니다. 날짜 요일 착오도 줄어듭니다.

2. 학생 상담/면담 기록 업데이트
왜 반복인가: 학생별 상담 파일을 찾거나 만들고, "면담 진행", "이력서 검토", "피드백 전달"을 추가하는 일이 반복됩니다.
자동화하면 좋은 점: "이경민 매드엔진 이력서 검토 추가"라고만 말해도 학생 폴더 탐색, 없으면 생성, 학생명.md 업데이트, 오늘 날짜 줄 병합까지 자동 처리할 수 있습니다.

3. 하루 기록 요약과 Obsidian 할일트래커 반영
왜 반복인가: 이미 매일 오전 6시에 하루 요약 Markdown 생성과 할일트래커 업데이트가 돌아가고 있습니다.
자동화하면 좋은 점: 루리가 "스픽 듀오링고 운동 완료"라고 보내는 순간 오늘 할일트래커까지 바로 체크되게 할 수 있습니다. 아침 6시까지 기다리지 않아도 되고, 기록 누락도 줄어듭니다.

05

LLM-wiki

  • "LLM-wiki"라는 용어 자체가 아직 업계에서 딱 하나로 정해진 게 아님
  • 실제로는 세 가지 정도의 서로 다른 개념이 이 이름으로 불림
Type 1

학습용 위키

사람이(또는 LLM 도움을 받아) LLM/AI 관련 개념을 위키 형태로 정리해놓은 것. 나무위키·위키백과처럼.

  • 예: "Transformer란?", "RAG란?", "토큰이란?" 문서가 서로 링크된 사이트
  • 누가 씀: 사람(또는 사람 + LLM 초안)
  • 용도: 학생 교육 자료, 강의 참고 자료
  • 만드는 법: Notion, GitBook, Obsidian, 정적 사이트 생성기(Docusaurus 등)로 구조를 짜고 GPT/Claude로 초안 작성 → 검수
Type 2

자동 갱신 위키

위키 자체를 AI 에이전트가 관리 — 질문받으면 문서를 자동 생성하고, 관련 문서끼리 알아서 링크를 걸고, 시간이 지나면 스스로 업데이트하는 지식베이스.

  • 예: Hermes의 메모리 시스템, OpenClaw의 MEMORY.md가 이 방향의 초기 형태
  • 누가 씀: LLM/에이전트가 대부분 자동으로
  • 용도: 팀/개인의 살아있는 지식창고, 리서치 아카이브
  • 만드는 법: 벡터 DB(임베딩 검색) + 에이전트 프레임워크로 "질문 → 문서 없으면 생성 → 있으면 갱신" 루프 구성
Type 3

코드 문서화 위키

깃허브 저장소 같은 걸 넣으면 LLM이 알아서 구조를 파악해서 설명 문서(위키)를 만들어줌.

  • 예: DeepWiki (NousResearch/hermes-agent 저장소를 자동 문서화한 것처럼)
  • 누가 씀: LLM이 코드를 읽고 자동 생성, 사람은 거의 손 안 댐
  • 용도: 오픈소스 프로젝트 온보딩 문서, 레거시 코드 이해
  • 만드는 법: DeepWiki 같은 기존 툴을 쓰거나, "저장소 스캔 → LLM 요약 → 위키 문서 생성 → 문서 간 링크" 파이프라인 구성
